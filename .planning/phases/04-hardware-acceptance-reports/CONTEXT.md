# Phase 4: Hardware Acceptance & Comparison Reports - Context

**Gathered:** 2026-10-26  
**Status:** Ready for execution  
**Target Audience:** Hardware suppliers, OEM workstation builders, system integrators, and AI enterprise procurement teams  
**Core Milestone:** Milestone 1 - Foundation & Scientific Integrity  

<domain>
## Phase Boundary
Phase 4 builds the presentation and verification layer that turns `qualification-run.json` artifacts generated by `hw-qual-cli` (or uploaded by users) into commercial hardware qualification certificates and analytical vs. measured comparison reports.

Key deliverables:
1. **Bundle Ingestion & Store**: Drag-and-drop or file upload for `qualification-run.json`, schema validation, sample fixture loader, and persistence via `@github/spark/hooks` (`useKV`).
2. **Analytical vs. Measured Delta Analysis**: Visual side-by-side comparison of pre-flight analytical predictions against empirical measured telemetry ($\Delta VRAM$, latency distributions P50/P90/P95/P99, throughput, and Goodput).
3. **Hardware Acceptance Certificate**: Clean, print-ready, tamper-evident qualification report featuring cryptographic machine fingerprints, OEM branding, Pass/Fail SLA checklist, and sign-off blocks.
</domain>

<decisions>
## Implementation Decisions

### 1. Navigation & App Integration (`src/App.tsx`, `TabMode`)
- Add a 4th top-level navigation tab: `acceptance` labeled **"Acceptance Reports"** with a badge indicator showing whether an empirical run is loaded.
- Seamless bridge: A button in the Workload Qualification tab ("Inspect Acceptance Report" / "Upload Benchmark Run") immediately navigates to this view with the matching workload context.

### 2. Ingestion & Schema Validation (`src/lib/engine/bundle-validator.ts`)
- Validate uploaded JSON against the `qualification-run.json` schema from `BENCHMARK_ADAPTER_ARCHITECTURE.md`.
- Provide built-in pre-loaded sample runs:
  - `Enterprise RAG on RTX 4090 (PASSED)`: compliant latency and memory fit.
  - `High-Concurrency Chatbot on RTX 2050 (FAILED - Out of Memory)`: illustrating over-capacity rejection.
  - `Code Assistant on L40S (PASSED)`: datacenter-class qualification.

### 3. Analytical vs. Measured Delta (`src/components/AcceptanceComparisonView.tsx`)
- Compute $\Delta VRAM = |VRAM_{\text{analytical}} - VRAM_{\text{measured}}|$ and error percentage.
- Render latency distribution bars comparing target SLA thresholds against actual P50, P90, P95, and P99 percentiles for TTFT and ITL.
- Visual Goodput meter showing the proportion of requests satisfying enterprise latency gates.

### 4. Commercial Acceptance Certificate (`src/components/AcceptanceCertificate.tsx`)
- Clean, high-contrast, professional design with printable `@media print` layout.
- Cryptographic verification badge displaying `system_hash` and run timestamp.
- Hardware specifications table (GPU topology, PCIe bandwidth, CUDA, host CPU/RAM).
- Formal 4-point verification checklist (Memory Capacity, TTFT SLA, ITL SLA, Zero OOMs).
- Sign-off block: Inspector name, machine serial number, partner company, and pass/fail seal.
- Actions: "Print / Save PDF", "Download qualification-run.json", and "Copy Shareable Link".
</decisions>
