# Plan 03-01: Hardware Environment Capture & Telemetry Sampler

## Goal
Build the environment capture module and background telemetry daemon in `src/cli/env-capture.ts` and `src/cli/telemetry.ts` to inspect physical machine specs (GPU model, driver, CUDA, PCIe link, CPU, RAM) and poll live VRAM watermarks at 100ms intervals during benchmark runs.

## Proposed Changes

### 1. Implement Environment Capture (`src/cli/env-capture.ts`)
- Function `captureSystemEnvironment()`:
  - Invokes `nvidia-smi` via Node `child_process.execSync` to capture:
    - GPU name, UUID, driver version, memory total, power limit, PCIe generation/width.
  - Queries OS release, platform, architecture, CPU model, core counts, and system RAM.
  - Fallback: If `nvidia-smi` is unavailable (e.g. CI runner, Mac, or simulated run), returns mock hardware environment with a clearly marked `isSimulated: true` flag.
  - Generates cryptographic `systemHash` (SHA-256) of machine attributes for audit provenance.

### 2. Implement Background Telemetry Sampler (`src/cli/telemetry.ts`)
- Class `GpuTelemetrySampler`:
  - `start(intervalMs = 100)`: Begins background asynchronous interval polling `nvidia-smi` for memory usage (`memory.used`), GPU utilization, temperature, and power draw.
  - `stop()`: Halts polling and computes:
    - `baselineVramGiB`: idle memory before benchmark
    - `peakVramGiB`: maximum memory watermark observed during benchmark
    - `peakGpuUtilizationPct`
    - `peakTemperatureC`
    - `samplesCount`: number of telemetry samples gathered

## Verification
- Unit test in `src/cli/__tests__/env-capture.test.ts` verifying:
  - System environment capture schema conformance.
  - Fallback behavior when `nvidia-smi` is mocked.
  - Cryptographic system hash generation.
