# Plan 06-01: Rig Inventory, Connection Registry & Fleet State Manager

## Goal
Implement the rig inventory management, connection registry, and live fleet state manager in `apps/server/src/` to track online physical rigs, manage pairing states, and expose fleet-wide machine inventory APIs.

## Proposed Changes

### 1. Connection Registry & Fleet Manager (`apps/server/src/fleet-manager.ts`)
- Implement `FleetManager` class maintaining in-memory active sockets and rig presence:
  - Track active desktop rig WebSockets by `rigId`.
  - Maintain rig status: `IDLE`, `BENCHMARKING`, `THROTTLED`, `OFFLINE`.
  - Broadcast rig presence changes to connected fleet dashboard subscribers.
  - Heartbeat monitor automatically flagging rigs as `OFFLINE` if no heartbeat is received within 15 seconds.

### 2. Rig Registration & Fleet REST Endpoints (`apps/server/src/routes/rigs.ts` or `apps/server/src/index.ts`)
- `POST /api/rigs/register`:
  - Ingest machine environment specs (`gpu`, `host`, `system_hash`, `hardware_uuid`, `partner_name`).
  - Generate stable `rigId` and rig authentication token.
- `GET /api/rigs`:
  - List all registered rigs across the factory floor with status, GPU specs, live power, and active benchmark run.
- `GET /api/rigs/:rigId`:
  - Detailed hardware topology and current health metrics.
- `POST /api/rigs/:rigId/heartbeat`:
  - Updates `lastHeartbeatAt` timestamp and current status.
