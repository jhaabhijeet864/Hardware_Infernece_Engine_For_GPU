# Plan 06-03: Benchmark Job Dispatching & Emergency Abort Protocol

## Goal
Implement the remote qualification job dispatching pipeline, multi-rig batch execution orchestrator, and real-time emergency halt signal relay in `apps/server/src/`.

## Proposed Changes

### 1. Job Dispatching Protocol (`packages/protocol/src/jobs.ts` or `apps/server/src/jobs/`)
- Define job schemas:
  - `QualificationJobDispatchSchema`:
    - `jobId`: UUID
    - `batchId`: UUID optional
    - `targetRigId`: UUID
    - `workloadSpec`: WorkloadSpecification
    - `slaGates`: { maxTtftMs: number, maxItlMs: number }
    - `oemBranding`: OEMBrandingConfig optional
    - `timeoutSeconds`: number default 600
  - `JobProgressEventSchema`:
    - `jobId`: UUID
    - `rigId`: UUID
    - `status`: 'INITIALIZING' | 'WARMUP' | 'BENCHMARKING' | 'COMPLETED' | 'FAILED' | 'ABORTED'
    - `progressPct`: number
    - `currentTtftMs`: number optional
    - `currentVramGiB`: number optional
    - `logMessage`: string optional

### 2. Job Endpoints (`apps/server/src/index.ts`)
- `POST /api/jobs/dispatch`:
  - Dispatch a single qualification job to a specific online rig.
  - Transmit payload through the rig's open WebSocket connection.
- `POST /api/batches/dispatch`:
  - Dispatch a batch qualification run across multiple selected online rigs.
  - Create `qualificationBatches` record in DB and broadcast batch status to fleet monitors.
- `POST /api/rigs/:rigId/abort`:
  - Transmit `EmergencyHaltCommand` directly to the connected rig's socket.
  - Immediately set rig status to `IDLE` and update job status to `ABORTED`.
- `POST /api/rigs/:rigId/runs`:
  - Ingest the finalized `qualification-run.json` bundle from the rig daemon upon run completion.
  - Store run metrics in database and generate certified URL.

### 3. Client Telemetry & Progress Relay
- Broadcast job progress events to any mobile/web client subscribed to `/ws/rigs/:rigId/watch` or `/ws/fleet/live`.

## Verification
- Unit test in `apps/server/__tests__/job-dispatch.test.ts` verifying job creation, WebSocket command transmission, progress event broadcasting, and emergency abort handling.
