# Plan 01-01: Engine Extraction & Architecture Database

## Goal
Extract estimation logic into a pure TypeScript module (`src/lib/engine/`) that calculates model weight memory and KV-cache memory using exact model architecture formulas, supports explicit GiB/GB units, and includes a verified registry of popular LLM architectures.

## Proposed Changes

### 1. Create Core Engine Types (`src/lib/engine/types.ts`)
- Define `ModelArchitecture`:
  - `modelId`: string
  - `name`: string
  - `family`: string (e.g. 'llama', 'mistral', 'gemma', 'qwen', 'deepseek', 'phi')
  - `paramCountTotal`: number (exact billion parameters)
  - `paramCountActive`?: number (for MoE architectures like Mixtral 8x7B, DeepSeek-V3)
  - `numLayers`: number ($L$)
  - `numAttentionHeads`: number ($H_Q$)
  - `numKeyValueHeads`: number ($H_{\text{KV}}$)
  - `headDimension`: number ($D_{\text{head}}$)
  - `vocabSize`: number
  - `contextWindowMax`: number
  - `attentionType`: 'MHA' | 'GQA' | 'MQA'
- Define `PrecisionFormat`: `'FP32' | 'FP16' | 'BF16' | 'INT8' | 'INT4' | 'FP8'`
- Define `EstimationStatus`: `'Analytical Estimate' | 'Calibrated Estimate' | 'Measured Result' | 'Unsupported'`
- Define `WorkloadEstimationInput`:
  - `modelArchitecture`: `ModelArchitecture` | string (preset ID)
  - `precision`: `PrecisionFormat`
  - `contextLength`: number
  - `batchSize`: number (concurrency)
  - `kvCachePrecision`?: `PrecisionFormat`
  - `cudaRuntimeOverheadGiB`?: number
- Define `WorkloadEstimationResult`:
  - `weightsGiB`: number
  - `weightsGB`: number
  - `kvCacheGiB`: number
  - `kvCacheGB`: number
  - `activationOverheadGiB`: number
  - `cudaContextGiB`: number
  - `totalVRAMRequiredGiB`: number
  - `totalVRAMRequiredGB`: number
  - `status`: `EstimationStatus`
  - `assumptions`: string[]
  - `warnings`: string[]

### 2. Implement Architectural KV Cache and Weight Formulas (`src/lib/engine/calculator.ts`)
- Model weights:
  $$\text{Bytes}_{\text{weights}} = P \times \text{bytesPerParam}$$
- KV Cache memory:
  $$\text{Bytes}_{\text{KV}} = 2 \times L \times H_{\text{KV}} \times D_{\text{head}} \times T \times B \times \text{bytesPerKVElem}$$
  (Factor 2 accounts for Keys and Values).
- Handle GQA ($H_{\text{KV}} < H_Q$), MQA ($H_{\text{KV}} = 1$), and MHA ($H_{\text{KV}} = H_Q$).
- Remove fake FlashAttention multiplier (`* 0.7`). FlashAttention saves peak activation memory during backprop and attention matrix computation, but does not compress stored KV cache tokens.
- Add CUDA context overhead: baseline ~0.6–1.0 GiB depending on GPU driver, plus a dynamic 2-3% memory buffer.

### 4. Provide Unit Conversion Utilities (`src/lib/engine/units.ts`)
- Explicit binary GiB ($2^{30} = 1,073,741,824$ bytes) vs decimal GB ($10^9 = 1,000,000,000$ bytes).
- Standard formatting helpers: `formatBytes(bytes: number, unit?: 'GiB' | 'GB')`.

## Verification
- Run a test script in Node verifying that Llama 3.1 8B at 8192 context length, FP16 precision, concurrency 1 produces:
  - Weights: ~14.96 GiB (16.06 GB)
  - KV Cache: $2 \times 32 \times 8 \times 128 \times 8192 \times 1 \times 2 = 1,073,741,824$ bytes = exactly 1.00 GiB (1.07 GB).
  - Total: ~16.5–17.0 GiB (with CUDA runtime overhead).
