# Plan 01-02: Engine Integration & Legacy Code Consolidation

## Goal
Integrate the new `@engine` module into the existing app, deprecate the arbitrary heuristic formulas in `src/lib/calculator.ts` and `src/lib/llm-calculations.ts`, and provide backwards-compatible wrappers so UI components consume verified calculations with explicit status and assumptions.

## Proposed Changes

### 1. Refactor `src/lib/calculator.ts`
- Replace the legacy heuristics:
  - Remove `parameters * 32 / 7` and `parameters * 4096 / 7`.
  - Remove `if (flashAttention) kvCacheGB *= 0.7`.
- Route `calculateMemoryRequirements` to use `src/lib/engine/calculator.ts`.
- When a model preset is selected, look up its architectural specs in `src/lib/engine/registry.ts`.
- If custom parameters are provided with no known architecture, compute an analytical estimate using standard GQA baseline assumptions (e.g. 32 layers, 8 KV heads, 128 head dim for ~7-8B; scaled proportionally with explicit warning: "Uncalibrated architectural fallback: assuming GQA 8 KV heads").

### 2. Refactor `src/lib/llm-calculations.ts`
- Deprecate duplicate `calculateInferenceMemory`.
- Delegate to `src/lib/engine/calculator.ts`.
- Update `calculateTrainingMemory`:
  - Mark result explicitly as `Experimental Analytical Estimate`.
  - Add documentation warning: "Training memory estimates are theoretical approximations. Actual memory depends heavily on activation checkpointing, sequence packing, and ZeRO stage."
- Update `getRecommendedGPUs`:
  - Filter GPUs by physical VRAM capacity vs total required GiB.
  - Compute `memoryOccupancyPercent = (requiredGiB / gpu.vramGiB) * 100`.
  - Categorize status:
    - If `memoryOccupancyPercent <= 75%`: `Comfortable Fit`
    - If `75% < memoryOccupancyPercent <= 95%`: `Tight Fit`
    - If `95% < memoryOccupancyPercent <= 100%`: `High Risk of OOM`
    - If `memoryOccupancyPercent > 100%`: `Insufficient VRAM (OOM)`

### 3. Update Preset Definitions
- Update `src/lib/constants.ts` and `src/lib/llm-calculations.ts` `MODEL_PRESETS` to reference the canonical registry entries in `src/lib/engine/registry.ts`.
- Include architecture badges (e.g. "GQA 8 KV Heads", "MLA MoE", "MHA 32 Heads").

## Verification
- Verify that calling legacy interfaces (`calculateMemoryRequirements`, `calculateInferenceMemory`) yields consistent, non-conflicting, mathematically verified numbers across all UI screens.
- Ensure build succeeds: `npm run build`.
