# Plan 01-04: Unit Test Suite & Validation

## Goal
Establish an automated unit testing suite for the calculation engine and verification pipeline, confirming mathematical correctness against real model architectures, GQA/MLA behavior, and edge cases.

## Proposed Changes

### 1. Configure Test Runner
- Add `vitest` to `devDependencies` (or configure a standalone test runner script using Node 24 native test runner `node:test`).
- Add `"test": "vitest run"` (or `"node --test"`) script to `package.json`.

### 2. Implement Engine Unit Tests (`src/lib/engine/__tests__/calculator.test.ts`)
- **Test Case 1: Llama 3.1 8B KV-Cache Exact Math**
  - Architecture: 32 layers, 8 KV heads, 128 head dim.
  - At 8,192 context length, FP16 precision (2 bytes/elem), batch size 1:
  - Theoretical KV cache bytes: $2 \times 32 \times 8 \times 128 \times 8192 \times 1 \times 2 = 1,073,741,824$ bytes.
  - Assert KV cache is exactly $1.00\text{ GiB}$ ($1.0737\text{ GB}$).
- **Test Case 2: GQA vs MHA Compression Verification**
  - If Llama 3.1 8B used MHA (32 KV heads), KV cache would be $4.00\text{ GiB}$.
  - Assert that GQA (8 KV heads) correctly produces $1.00\text{ GiB}$ (4x compression factor).
- **Test Case 3: Model Weights Precision Scaling**
  - 8.03B parameters at FP16 (2 bytes) = $16.06\text{ GB} = 14.957\text{ GiB}$.
  - 8.03B parameters at INT4 (0.5 bytes) = $4.015\text{ GB} = 3.739\text{ GiB}$.
  - Assert weight calculations match exact byte conversions.
- **Test Case 4: DeepSeek-V3 / MoE Architecture Handling**
  - Verify total parameter weight storage (671B params) is distinguished from active routing parameters (37B params).
- **Test Case 5: Concurrency / Batch Scaling**
  - Increasing batch size from 1 to 4 should scale KV cache linearly ($4\times$) while keeping model weights constant.
- **Test Case 6: Edge Cases & Validation Guardrails**
  - Context length 0 or negative throws validation error or is clamped.
  - Unknown model architecture falls back gracefully with explicit warnings.

### 3. Implement Verification Script (`src/lib/engine/__tests__/verify-models.ts`)
- Script that runs through all presets in `registry.ts` and outputs a benchmark matrix of:
  - Model Name | Total Params | Active Params | KV Type | Weights (GiB) | KV Cache 4k (GiB) | Minimum GPU
- Log results to confirm all presets pass sanity checks without NaN or negative values.
