# Plan 02-02: Workload Builder UI Component & Traffic Sizing

## Goal
Build an interactive `WorkloadBuilder` component in `src/components/WorkloadBuilder.tsx` that lets users configure real-world deployment parameters (workload archetype presets, runtime, sequence distributions, active concurrency vs total users, SLA targets) with rich feedback and instant validation.

## Proposed Changes

### 1. Create `src/components/WorkloadBuilder.tsx`
- **Archetype Selector Bar**: Fast-click cards for Enterprise RAG, Customer Support, Code Assistant, and Agentic Reasoning with visual badges.
- **Model & Runtime Configuration**:
  - Model dropdown populated from canonical `MODEL_REGISTRY`.
  - Runtime selector: `vLLM` (Recommended for High Throughput), `TensorRT-LLM` (Lowest Latency), `Ollama` (Workstation/Edge).
  - Precision selector (`FP16`, `BF16`, `INT8`, `FP8`, `INT4`).
- **Token Distributions (P50 & P99)**:
  - Input Prompt Length: P50 slider/input + P99 peak slider.
  - Output Generation Length: P50 slider/input + P99 peak slider.
- **Traffic Sizing (Concurrency vs Total Users)**:
  - Slider for `Active Concurrent Requests` ($B$, 1 to 64).
  - Explanatory callout:
    > *"Concurrency represents simultaneous active generating streams hitting the GPU at any given instant. A team of 200 users typically generates 4–8 concurrent active requests under normal business hours."*
- **SLA Target Inputs**:
  - Max acceptable TTFT (Time To First Token) target in ms (e.g. 500 ms).
  - Target ITL (Inter-Token Latency) in ms/token (e.g. 35 ms/token = 28 tokens/sec).

### 2. State & KV Integration
- Persist active workload state seamlessly using `@github/spark/hooks` `useKV('active-workload-spec', ...)`.
- Update `App.tsx` to mount `WorkloadBuilder` alongside the refined results and GPU matchmaker.

## Verification
- Confirm smooth slider interaction and preset switching.
- Verify that changing concurrency instantly recalculates KV-cache footprint in real-time.
- Verify responsive layout on mobile, tablet, and desktop.
