# Plan 07-01: Native Sensor Daemon & Multi-GPU Telemetry Collector

## Goal
Implement the continuous hardware sensor loop and multi-GPU telemetry collector in `apps/desktop/` that collects physical NVML / DXGI / system metrics and streams live `GpuTelemetryFrame` payloads to both the local UI and the central fleet gateway over WebSocket.

## Proposed Changes

### 1. Sensor Service (`apps/desktop/src/sensor-service.ts`)
- Implement `DesktopSensorService`:
  - Poll hardware telemetry via Tauri IPC (`get_gpu_telemetry`) or local fallback when running in browser dev mode.
  - Ingest host system metrics: OS platform, CPU utilization %, and RAM total/used.
  - Assemble validated `GpuTelemetryFrame` schemas from `@hardware-inference/protocol`.
  - Handle multi-GPU aggregation (e.g. Dual RTX 4090 or quad-GPU workstation).
  - Expose observable/callback stream for UI components.

### 2. Live Cloud Gateway Streamer (`apps/desktop/src/cloud-streamer.ts`)
- Maintain auto-reconnecting WebSocket connection to the fleet gateway:
  - Target: `ws://<server>/ws/rigs/:rigId/stream`.
  - Transmit `TELEMETRY_FRAME` messages at 500ms intervals during active benchmarking and 2000ms intervals when idle.
  - Handle network drops with backoff and local queueing.

## Verification
- Unit test in `apps/desktop/__tests__/sensor-service.test.ts` verifying frame generation, multi-GPU metric aggregation, and WebSocket streaming payload conformance.
