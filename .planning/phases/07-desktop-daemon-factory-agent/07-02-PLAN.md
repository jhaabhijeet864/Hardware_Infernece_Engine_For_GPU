# Plan 07-02: Remote Qualification Job Worker & Subprocess Runner

## Goal
Implement the remote job execution worker in `apps/desktop/src/job-worker.ts` that receives benchmark dispatches from the cloud gateway, executes `hw-qual-cli` locally with customer workload parameters, emits live progress events, and uploads the completed qualification bundle.

## Proposed Changes

### 1. Job Worker Core (`apps/desktop/src/job-worker.ts`)
- Listen on the desktop rig's open WebSocket connection for incoming `EXECUTE_JOB` commands (`QualificationJobDispatchSchema`).
- Job Execution Lifecycle:
  1. Transition state to `INITIALIZING` and notify cloud gateway with `JobProgressEvent` (0%).
  2. Spawn benchmark runner (`npx hw-qual run` or internal execution adapter) passing:
     - Model ID
     - Prompt and generation token targets
     - Concurrency limit
     - Output bundle destination
  3. Stream periodic progress updates:
     - `WARMUP` (15%)
     - `BENCHMARKING` (25% - 90%) with current live TTFT/ITL and VRAM occupancy
     - `COMPLETED` (100%) or `FAILED`
  4. On completion, read generated `qualification-run.json` and upload to `POST /api/rigs/:rigId/runs`.
  5. Return machine status to `IDLE`.

### 2. Emergency Halt Handling
- Listen for `EMERGENCY_HALT` messages.
- Immediately terminate child benchmark processes, purge VRAM allocations via OS signal, and notify the gateway of the abort.

## Verification
- Unit test in `apps/desktop/__tests__/job-worker.test.ts` verifying dispatch handling, progress event emission, bundle upload, and abort handling.
