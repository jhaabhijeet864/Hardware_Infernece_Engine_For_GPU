# Plan 05-02: Co-branded Qualification Templates & OEM Customization

## Goal
Build OEM co-branding customization into the `AcceptanceCertificate` and provide an `OEMBrandingModal` allowing suppliers and integrators to configure company branding, facility locations, and warranty disclaimer clauses.

## Proposed Changes

### 1. OEM Branding Model (`src/lib/types/branding.ts` or `src/lib/engine/branding.ts`)
- Define `OEMBrandingConfig`:
  - `partnerName`: string (e.g. "Shenzhen Compute Systems", "Apex AI Workstations")
  - `partnerTagline`: string
  - `facilityLocation`: string (e.g. "Factory QA Lab #4, Building B")
  - `warrantyClause`: string (terms of hardware performance acceptance)
  - `certifierTitle`: string (e.g. "Chief AI Infrastructure Auditor")
  - `defaultBadgeColor`: `'emerald' | 'cyan' | 'purple'`

### 2. Branding Customizer Modal (`src/components/OEMBrandingModal.tsx`)
- Dialog allowing user/partner to update branding fields.
- "Save as Default Factory Profile" button.
- "Reset to Generic AI Lab" button.

### 3. Update Acceptance Certificate (`src/components/AcceptanceCertificate.tsx`)
- Display custom partner logo banner, partner name, facility, and warranty clause.
- Ensure customized branding formats cleanly in `@media print` PDF outputs.

## Verification
- Unit test for branding config serialization and validation.
- Visual inspection of certificate rendering with customized OEM branding.
